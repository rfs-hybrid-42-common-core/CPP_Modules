# 🟢 Exercise 02: Array

## 📝 Objective
Develop a class template `Array` capable of containing elements of any type `T`. The class must manage its own memory, supporting an empty constructor, a parameterized constructor that allocates an array of `n` default-initialized elements, and deep-copy semantics via the Orthodox Canonical Form. Memory must be strictly allocated using `new[]` and freed with `delete[]`. Finally, element access must be provided through the subscript operator (`[]`), which must actively check for out-of-bounds access and throw an exception if an invalid index is requested.

## 💡 The Logic

This exercise combines the generic programming concepts of C++ templates with rigorous dynamic memory management and exception safety.

1. **Class Templates & `.tpp` Inclusions:** 
   Just like function templates, class templates are blueprints. The compiler must see the full implementation to generate a specific class (like `Array<int>` or `Array<std::string>`) at compile time. To keep the `.hpp` file readable while satisfying this compiler requirement, the implementation is written in a `.tpp` (template implementation) file, which is explicitly included at the very bottom of `Array.hpp`.
2. **Default Initialization (`new T[n]()`):** 
   When dynamically allocating an array of generic types, simply calling `new T[n]` leaves primitive types (like `int`) uninitialized, filling them with garbage memory. Appending the parentheses `new T[n]()` forces value-initialization, ensuring primitives are safely zeroed out while still properly calling the default constructors for complex objects.
3. **Deep Copies & Memory Ownership:** 
   Because the `Array` class owns a dynamically allocated pointer (`_elements`), the default copy behaviors generated by the compiler (shallow copies) would cause multiple objects to point to the exact same memory address, leading to catastrophic double-free crashes. The copy constructor and assignment operator are meticulously overloaded to allocate brand new memory arrays and copy the values over one by one, ensuring total independence between objects.
4. **Bounds-Checked Access:** 
   Raw C++ arrays do not know their own size and will blindly allow you to read or write memory outside their bounds, causing segmentation faults or silent corruption. The `Array` class overrides `operator[]` (both mutable and `const` versions) to compare the requested index against the internal `_size`. If the index is out of bounds, it immediately intercepts the illegal memory access and `throws` a `std::out_of_range` exception.
